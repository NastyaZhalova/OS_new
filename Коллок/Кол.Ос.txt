1. Объектно-ориентированное программирование — это концепция разработки программного обеспечения, основанная на моделировании системы через взаимодействие объектов, 
каждый из которых инкапсулирует состояние (данные) и поведение (методы). Ключевые принципы: инкапсуляция, наследование, полиморфизм, абстракция. 
Цель — управление сложностью через локализацию изменений, повторное использование и масштабируемость архитектуры.

2. Это метод структурирования системы, при котором она разбивается на взаимодействующие объекты, отражающие реальные или логические сущности предметной области.
В отличие от алгоритмической декомпозиции, объектная ориентирована на устойчивость к изменениям: поведение распределяется по объектам, а не централизуется. 
Пример: вместо функции processOrder() — объект Order, у которого есть методы validate(), submit(), cancel().

3. Дизайн программного обеспечения — это процесс принятия архитектурных решений, определяющих структуру, поведение и взаимодействие компонентов системы. 
Он включает выбор паттернов, интерфейсов, зависимостей, уровней абстракции. 
Примеры:
MVC в веб-приложениях
DI (Dependency Injection) в тестируемых системах
CQRS в распределённых системах
Hexagonal Architecture в изолированных доменах

4. Согласно Джорджу Миллеру, человек способен удерживать в кратковременной памяти 7±2 элемента. В IT это проявляется в ограничениях когнитивной нагрузки:
Примеры:
Количество элементов в меню интерфейса (UI/UX)
Размер группы тестов в одном тесткейсе
Число параметров функции (больше — признак плохого дизайна)
Количество сущностей на диаграмме UML
Количество открытых вкладок IDE, прежде чем теряется фокус
Количество одновременно отслеживаемых логов при отладке
Число компонентов в одном модуле (SRP — Single Responsibility Principle)

5. Гради Буч выделяет 5 признаков сложных систем:
Иерархичность — система состоит из подсистем, каждая из которых может быть рассмотрена отдельно.
Эмерджентность — поведение системы не сводится к поведению её частей.
Абстракция — управление сложностью через скрытие деталей.
Сложность — множество взаимодействующих компонентов.
Эволюционность — система развивается во времени.
Примеры:
A. Операционная система Linux
Иерархичность: ядро → драйверы → процессы
Эмерджентность: поведение multitasking не сводится к поведению scheduler
Абстракция: системные вызовы скрывают реализацию
Сложность: миллионы строк кода, тысячи модулей
Эволюционность: развивается с 1991 года

B. Система онлайн-банкинга
Иерархичность: frontend → backend → БД → API
Эмерджентность: безопасность — результат взаимодействия слоёв
Абстракция: REST API скрывает бизнес-логику
Сложность: множество ролей, сценариев, интеграций
Эволюционность: постоянные обновления, новые фичи

C. Система CI/CD (например, GitHub Actions)
Иерархичность: workflow → job → step → action
Эмерджентность: автоматизация сборки и тестов
Абстракция: YAML скрывает реализацию скриптов
Сложность: параллельные пайплайны, зависимости
Эволюционность: адаптация под новые технологии
